# Apps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** apps after the reference platform: another provider's web application shown in the back office, installed from its XML definition, opened with a signed request.

**Architecture:**
- **The definition and signing:** `src/lib/appDefinition.js`, a small XML reader of our own and `sign()`.
- **The apps:** `src/domain/apps.js` and tenant migration 049 (`apps`, `app_extension_points`, `app_launches`).
- **Routes:** `src/routes/apps.js` (`/api/apps` and the launch page `/apps/frame/:tenant/:token`).
- **Console:** `public/js/apps.js` (Administration > Apps and the tabs on pages) and `public/js/appframe.js`.

**Spec:** `platform/docs/audits/audit-apps.md`. On 5 October 2026 John accepted the nine defaults.

## Global Constraints

- **Vendor name:** never in code, docs or commits.
- **Writing style:** no em dashes.
- **The App Key** is sealed and never returned; the signed request never reaches the console's code.
- **Outbound:** definitions and install calls go through the outbound guard.
- **CSP:** the console allows HTTPS frames and keeps `form-action 'self'`; the launch page allows a form post to one app's origin.
- **Deployed behaviour:** nothing changes for a SACCO with no apps.
