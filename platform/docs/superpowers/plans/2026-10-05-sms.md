# SMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SMS after the reference platform, pluggable: a provider interface with a generic HTTPS gateway built in, templates of type SMS, delivery through the dispatcher, delivery reports, manual SMS and subscriptions.

**Architecture:**
- **The channel:** `channels/sms.js` is the SMS channel. It handles E.164 numbers, segment counting and the six-segment limit.
- **Providers:** `channels/sms-providers/` holds the registry, `http.js`, and a README with the interface.
- **Shared with Email:** the dispatcher, subscriptions and manual sending are Email's.

**Spec:** `platform/docs/audits/audit-sms.md`. On 5 October 2026 John accepted the nine defaults, and asked for delivery reports (decision 7).

## Global Constraints

- **Vendor name:** never in code, docs or commits.
- **Writing style:** no em dashes.
- **Providers:** no company's gateway is built in.
- **The gateway:**
  - its URL goes through the outbound guard;
  - its API key is sealed and goes to no other gateway;
  - values are escaped for JSON or form encoding.
- **Numbers:** E.164 from the tenant's country.
- **Length:** at most six segments.
- **Outcomes:**
  - `SMS_SERVICE_NOT_ENABLED`, `MISSING_SMS_RECIPIENT` and `UNDEFINED_DESTINATION`;
  - `INVALID_SMS_GATEWAY_CREDENTIALS` (401 and 403);
  - `SMS_GATEWAY_ERROR`: a 4xx answer fails at once; a 5xx answer or a network error is retried.
- **Delivery reports:** sent to `/hooks/sms/<tenant>/<token>`. The token is shown once and only its hash is kept. The provider's fields map the report to DELIVERED or UNDELIVERED.
- **Permissions:**
  - SEND_MANUAL_SMS is new, for managers and administrators;
  - settings are read by template users and changed by administrators.
